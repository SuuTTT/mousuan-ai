# 发布清单

## A. 冻结内容

- [ ] 确认版本号、发布日期和发布标题。
- [ ] 甲方确认首页五个问题、“1 + 1 + 3 + 1 + 5”结构及团队介绍。
- [ ] 术语表、三部著作信息和主要引用已校核。
- [ ] `CHANGELOG.md` 中不存在应归入本版本的“未发布”条目。

## B. 仓库检查

- [ ] 工作树干净，发布提交只包含本版本内容。
- [ ] README、package 版本和发布说明一致。
- [ ] 未跟踪 `.env`、token、私钥、证书或服务器凭据。
- [ ] 对完整 Git 历史执行敏感信息扫描。
- [ ] 决定仓库和内部手稿资料的公开范围。
- [ ] GitHub `main` 与本地 release commit 一致。

## C. 自动验证

```bash
npm ci
npm run release:check
git diff --check
```

- [ ] 构建成功。
- [ ] 所有渲染测试通过。
- [ ] 39 个公开路由均成功生成。
- [ ] `.release/site` 不包含内部审稿资料。
- [ ] GitHub Actions 在 release commit 上通过。

## D. 人工验收

- [ ] 首页中文和英文内容正确。
- [ ] 五个问题、一个范式、一个中心、三个定义、孙子模型和五大模块入口准确。
- [ ] 活动与文章入口可达，论坛报告人与报告题目准确。
- [ ] 团队照片不裁切，三部著作链接准确。
- [ ] 定理搜索、公式 MathML 和原著链接正常。
- [ ] Android Chrome 与 iOS Safari 可以导航、滚动和返回主页。
- [ ] 不出现 emoji 箭头、孤字行、prompt 回复或内部手稿入口。

## E. GitHub Release

1. 在最终 release commit 创建带说明的标签：`v0.9.0`。
2. 推送 `main` 与标签。
3. 从标签创建 GitHub Release，并粘贴 `docs/releases/v0.9.0.md` 的摘要。
4. 上传经过检查的静态发布包或校验文件；不要上传内部资料。
5. 标签发布后不移动；修复使用 `v0.9.1`。

## F. 部署与记录

- [ ] 以标签名称创建不可变服务器 release 目录。
- [ ] 切换 `current` 并重启服务。
- [ ] 公开地址返回 HTTP 200，关键文案和静态资源存在。
- [ ] 记录 tag、commit SHA、部署时间、发布目录与上一个可回滚版本。
- [ ] 保留上一版本，禁止就地覆盖或删除。

## G. 正式域名切换

- [ ] 确认正式地址为 `https://mousuan.net`，`https://www.mousuan.net` 永久跳转至主域名。
- [ ] 若启用 `https://staging.mousuan.net`，它仅用于受限验收且不被搜索引擎收录。
- [ ] AWS 或阿里云生产资源、账号责任人、账单和备份策略已确认。
- [ ] HTTPS 证书生效，HTTP 自动跳转 HTTPS。
- [ ] 中国大陆节点启用前已完成适用的 ICP 备案。
- [ ] DNS 切换前降低 TTL，并保留原审阅地址作为短期回滚入口。
